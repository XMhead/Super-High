# Super High 界面约束

## 规则

- 技术栈固定：Vue 3、Vite、Tauri 2、Rust。
- 做真实应用界面，不要营销页或占位 UI。
- 设置页标题只显示名称，不附加讲解小字；适用于已有页面和新增分类。需要说明的选项放在对应设置行，不另写标题副说明。
- 设置页采用“个人 / 集成”侧栏分组与紧凑设置行：名称在左、控件在右，插件放“集成”，主题用下拉选择，不铺满主题卡片。设置开关按已确认参考使用小型滑动开关。
- 浏览器实时预览与交互模拟使用 [superhigh-html](../superhigh-html/SKILL.md)，直接复用应用组件；显式模拟场景可使用标明来源的模拟数据，不能把模拟结果当作桌面后端验收。
- 使用 `src/lib/theme.ts` 与 `src/styles.css` 中的全局主题变量；若已有主题 token，不要硬编码一次性颜色。
- Markdown 内容复用 `src/lib/markdown.ts` 的 `renderMarkdown` 与 `markdown-body` 样式；文件阅读复用 `EditorPane.vue` 的标签和预览，不把 Markdown 源码作为最终阅读界面另造纯文本区。
- 去掉占位或虚假内容，例如 `plugins`、演示项目名、假数量、假计时器、写死的状态文案等。
- 控件偏**密**、偏**矩形**：按钮应为方形或矩形，圆角仅允许较小值。
- 普通控件不要用药丸形、正圆、球体、气泡、胶囊等样式。
- 卡片圆角不超过 8px。**项目 Skills**：以信息密度为先——可用**多列紧凑卡片网格**或横向长条行，避免单行一项却占大块空白；与产品当前布局保持一致。
- 操作状态要一眼能看懂。Skills 需在明显的方形/矩形状态区展示启用数量，例如 `3/4 已启用`。
- 功能按钮组在放得下时尽量**单行横排**；不要把少量按钮拆成多行稀疏散布。
- 工具栏可能溢出时，保持单行：标签紧凑 + **横向滚动**，而不是自动换行堆多行。
- 项目编辑器只能保留一份同一资源的导航、搜索和文件列表：接入 SuperHigh 原生资源管理器时，必须删除项目 HTML 中对应的旧侧栏/列表，搜索应放进原生资源管理器标题栏。用户已主动选择打开的编辑器、文件或页面，不要再用无操作价值的重复标题占空间。
- 面包屑、菜单、下拉框、右键菜单等浮层必须锚定实际触发控件；不要固定到整条工具栏或容器左上角。
- 深色界面里的浮层和按钮状态禁止白色光晕、默认亮色 halo、发白描边或发光阴影；优先用主题边框、纯色 hover/active 和 `box-shadow: none`。
- 浮层列表字号、行高和触发区域保持一致，除非同一界面已有明确层级规范。
- 在桌面宽与窄宽下都要核对文案是否放得下；命令标签不要重叠或被裁切。

## 桌面 UI 定位与验收

- 文件树与分栏先定位 `src/components/WorkspaceShell.vue`（布局）、`ExplorerPane.vue`（资源管理器）、`FileTreeNode.vue`（树行）；文件管理区在 `FileManagerPanel.vue`，编辑器在 `EditorPane.vue`，共享样式在 `src/styles.css`。用 `rg -n` 定位相关声明、模板和样式块，再按段读取。
- 文件资源管理器复用 `ExplorerPane`、`FileTreeNode` 及工作区的展开状态和宽度设置；接入后删除旧组件、独立状态和专用样式。移除标题或路径行时，同步调整相邻区域的布局行定义。
- 桌面自动化沿用根指令的实际入口和会话保护；从 `src-tauri/src/lib.rs` 确认自动化启动参数与端口，首次启动即带参数。用 `agent-browser --cdp <现场端口> snapshot -i -s <目标选择器>` 检查目标区域。`errors --json` 在执行进程内按首行去重计数，定位时再取对应堆栈。
- PowerShell 中的 Agent Browser 引用参数用引号传入，如 `click '@e1'`；截图按当前 CLI 帮助指定项目临时目录，并以返回路径核对实际落点。
- 宽、窄窗口验收使用 Tauri 原生窗口尺寸，在允许范围内调整并恢复原尺寸；不要对桌面 WebView 使用 `set viewport` 或设备模拟。若已有覆盖，解除持有覆盖的自动化连接并清除设备尺寸覆盖，不用关闭应用恢复。核对页面视口、原生窗口客户区与系统缩放匹配后再交付；仅新建 CDP 连接执行清除不代表原连接的覆盖已解除。
- 白边、整体偏移或裁切先比对真实窗口与页面视口，再查目标元素的 `getBoundingClientRect()` 和滚动范围；页面内部截图或根元素位于原点不能证明窗口显示正常。视口匹配后仍裁切才修布局，并验证原问题场景。
- 启动页定位 `WelcomeScreen.vue` 与 `src/styles.css` 的 `.welcome-screen`、`.welcome-panel`；最近项目较多或路径较长时，核对顶部入口可见、末条可滚动到达且无横向溢出。超高内容不能因居中落到负坐标。

## 手机 UI 实时预览

- 用户要求在电脑实时修改、预览手机 UI 时，先复用或启动 `npm run mobile:dev`，立即提供可访问的手机尺寸预览。入口与 Host 代理见 [vite.mobile.config.ts](../../../vite.mobile.config.ts) 和 [手机界面更新](../../../README.md#手机界面更新)；`mobile:build` 生成的静态页面不能替代热更新预览。
- 预览使用真实 `MobileApp`，分别核对页面可见、连接真实 Host、保存源码后热更新。HTTP 成功或构建通过不等于用户已看到界面；已有可用预览和确认直接复用。
- 浏览器控制不可用或打开操作被拒绝时，直接给链接让用户打开；只有工具观察或用户确认后，才表述为“已显示”。
- 用户继续使用的预览服务保持运行。预览迭代先确认 UI，正式交付再按发布流程打包，不为每次预览修改反复构建安装包。

## 验收

按本次 diff 核对上面的相关约束；只在修改相应文案、圆角、光晕或浮层定位时检查该项。构建与实际入口验收沿用发布技能的收口流程，正式构建包含前端检查。
