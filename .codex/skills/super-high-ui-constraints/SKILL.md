# Super High 界面约束

## 规则

- 技术栈固定：Vue 3、Vite、Tauri 2、Rust。
- 做真实应用界面，不要营销页或占位 UI。
- 用户偏好清晰的面板分割。顶部工具栏与正文分栏共用布局基准，各控件明确归属对应面板，边缘精确对齐。
- 顶部搜索框贴合代码预览的分割线边缘，排序框贴合 CLI 一侧起点；保留实际分割线宽度，左右布局交换时镜像处理。
- 设置页标题只显示名称，不附加讲解小字；适用于已有页面和新增分类。需要说明的选项放在对应设置行，不另写标题副说明。
- 设置页采用“个人 / 集成”侧栏分组与紧凑设置行：名称在左、控件在右，插件放“集成”，主题用下拉选择，不铺满主题卡片。设置开关按已确认参考使用小型滑动开关。
- 浏览器实时预览与交互模拟使用 [superhigh-html](../superhigh-html/SKILL.md)，直接复用应用组件；显式模拟场景可使用标明来源的模拟数据，不能把模拟结果当作桌面后端验收。
- 使用 `src/lib/theme.ts` 与 `src/styles.css` 中的全局主题变量；若已有主题 token，不要硬编码一次性颜色。
- 字体功能必须同时接入 `@font-face`、全局字体变量和真实消费者；分别核对界面、正文、Monaco 编辑器与 xterm 终端，切换后确认实际字体选项刷新。DOM 文字按 [字体实测](../superhigh-html/SKILL.md#验收与排错) 核对字形来源；画布终端仍需核对渲染配置及实际显示。
- 所有可见文字、编辑器和终端字体必须消费 `--font-ui`、`--font-content`、`--font-mono` 或 `font: inherit`；组件、共享 CSS、移动端 CSS、内嵌预览和第三方编辑器配置中禁止硬编码系统字体族或 `monospace`、`sans-serif` 等通用族。Fallback 只允许集中在 `src/lib/fontStyles.ts` 和根变量初始化中，新增消费者必须同步接入当前字体变量和对应字重。
- 字重参数以 `src/lib/typography.ts` 为唯一运行时来源；默认档位保持 `500/600/700`，调整时不得降低已有 `500` 及以上文字。需要比较或回滚时切换现有 profile，不在组件内新增数字字重。Serif 正文可做局部视觉补偿，但代码块和终端仍保持等宽字重。
- Markdown 内容复用 `src/lib/markdown.ts` 的 `renderMarkdown` 与 `markdown-body` 样式；文件阅读复用 `EditorPane.vue` 的标签和预览，不把 Markdown 源码作为最终阅读界面另造纯文本区。
- 文本编辑按文件编码读取，每个标签保存自己的编码；普通保存沿用原编码。
- 混合编码或目标编码无法无损表示内容时，阻止默认写回；提供显式选择目标编码的转换入口。
- 日志文本可含 ANSI `ESC`；探测器不能仅凭 `ESC` 判为二进制。
- 去掉占位或虚假内容，例如 `plugins`、演示项目名、假数量、假计时器、写死的状态文案等。
- 控件偏**密**、偏**矩形**：按钮应为方形或矩形，圆角仅允许较小值。
- 普通控件不要用药丸形、正圆、球体、气泡、胶囊等样式。
- 卡片圆角不超过 8px。**项目 Skills**：以信息密度为先——可用**多列紧凑卡片网格**或横向长条行，避免单行一项却占大块空白；与产品当前布局保持一致。
- 操作状态要一眼能看懂。Skills 需在明显的方形/矩形状态区展示启用数量，例如 `3/4 已启用`。
- 功能按钮组在放得下时尽量**单行横排**；不要把少量按钮拆成多行稀疏散布。
- 确认对话框固定左确认、右取消；删除确认和输入确认复用 [AppDialog.vue](../../../src/components/AppDialog.vue) 的默认顺序。
- 工具栏可能溢出时，保持单行：标签紧凑 + **横向滚动**，而不是自动换行堆多行。
- 项目编辑器只能保留一份同一资源的导航、搜索和文件列表：接入 SuperHigh 原生资源管理器时，必须删除项目 HTML 中对应的旧侧栏/列表，搜索应放进原生资源管理器标题栏。用户已主动选择打开的编辑器、文件或页面，不要再用无操作价值的重复标题占空间。
- 文件图标统一使用 `src/lib/fileIcons.ts` 的映射和全局 `tree-kind-icon` 样式；编辑器标签、打开文件列表、面包屑、文件管理网格和手机文件列表不得各自维护扩展名映射或绘制另一套文件图标。
- 来源标识统一使用 [SourceBadge.vue](../../../src/components/SourceBadge.vue)。唤起指令与脚本工具共用其文字、颜色和边框；后续来源入口直接复用，禁止复制样式。
- 脚本工具来源固定“全部 / 全局 / 项目”。三个按钮等宽，并与卡片左右边缘对齐；卡片点击选中并展开，路径按钮阻止冒泡。选择通过 AppSettings 按工作区保存。
- 编辑器的打开文件列表按钮放在 MD/YAML 控件右侧。浮层纵向对齐按钮顶部，横向贴合代码预览与 CLI 分割线外沿；布局交换时镜像，不留额外间距。
- 顶部文件标签与展开列表统一复用 [EditorFileTab.vue](../../../src/components/EditorFileTab.vue) 和全局 `.editor-tab` 样式。图标、字体、字号、字重、颜色、间距及分割边框只有一份维护源；列表仅增加纵向布局、溢出和方向规则。
- 展开列表悬停时复用当前代码预览渲染器，只改变面板内临时预览。移出或取消恢复原文件；点击才提交工作区选择。悬停不得改写内容、打开历史或持久选中项。
- 面包屑、菜单、下拉框、右键菜单等浮层必须锚定实际触发控件；不要固定到整条工具栏或容器左上角。
- 深色界面里的浮层和按钮状态禁止白色光晕、默认亮色 halo、发白描边或发光阴影；优先用主题边框、纯色 hover/active 和 `box-shadow: none`。
- 普通控件的键盘焦点复用全局 `:focus-visible` 主题色细线，不使用浏览器原生黑色轮廓。焦点线向内绘制，避免在密集布局中被挤压或裁切；组件自定义焦点也必须使用主题变量。
- 窄侧栏的行内编辑必须保留名称输入宽度；放不下输入与操作时，保存和取消在下一行并排。备忘录分类输入保持静态名称的居中位置、字号和行高，并保留右侧操作列。验收编辑、焦点、保存及取消状态。
- 浮层列表字号、行高和触发区域保持一致，除非同一界面已有明确层级规范。
- 在桌面宽与窄宽下都要核对文案是否放得下；命令标签不要重叠或被裁切。

## Codex 标题配色

- 用户提到“Codex 标题配色”时，使用 Codex CLI `/resume` 的 14 色标题方案。
- 统一复用 [theme.ts](../../../src/lib/theme.ts) 的 `memoTitleColor(stableId)`；色板以同文件的 `MEMO_TITLE_RGB` 为权威源。
- 深色主题使用 Catppuccin Mocha 亮色，浅色主题使用 Catppuccin Latte；RGBA 的 Alpha 固定为 `1`。
- 原版输入为完整会话 ID 的 UTF-8 字节；复用时传稳定对象 ID，名称、时间和列表位置不参与分配。
- 分配采用 FNV-1a 64 位哈希。初值为 `0xcbf29ce484222325`，逐字节异或后乘 `0x100000001b3`，每步保留低 64 位。
- 最终哈希对色板长度取模，得到从 `0` 开始的色板索引；精确实现统一由 `memoTitleColor` 承载。
- 同一色板下，改名、排序、增删其它对象和重开保持同色；不同对象允许同色，相邻对象无需异色。
- 原版从当前语法主题按 scope 顺序提取前景色，末尾追加主题 accent，再按首次出现顺序去重。
- 原版排除基础文字色、背景色、注释色、标点色，以及配有特殊背景的前景色；默认 Mocha、Latte 各得到 14 色。
- 本项目复用默认色板的原始顺序；色板内容、顺序或长度改变会影响既有分配结果。
- 新消费者通过 `buildSurfaceVars` 注入的 `--memo-title-0` 至 `--memo-title-13` 使用配色；核对改名及重开后颜色不变。

## 桌面 UI 定位与验收

- 文件树与分栏先定位 `src/components/WorkspaceShell.vue`（布局）、`ExplorerPane.vue`（资源管理器）、`FileTreeNode.vue`（树行）；文件管理区在 `FileManagerPanel.vue`，编辑器在 `EditorPane.vue`，共享样式在 `src/styles.css`。用 `rg -n` 定位相关声明、模板和样式块，再按段读取。
- 文件资源管理器复用 `ExplorerPane`、`FileTreeNode` 及工作区的展开状态和宽度设置；接入后删除旧组件、独立状态和专用样式。移除标题或路径行时，同步调整相邻区域的布局行定义。
- 新增占满工作区的面板（与 `FileManagerPanel`、`GitPanel` 同级）时，把根类名加入 `src/styles.css` 中 `.workspace-main.activity-bar-hidden :is(...)` 列表，否则隐藏活动栏后面板仍从第 2 列开始、左侧空出一列。组件 scoped 样式不要写 `:global(.a) .b`：Vue 只编译出 `.a`，后代选择器被丢弃，规则会落到父级网格上。
- 分栏对齐按实际控件与面板的边缘坐标验收；拖动分割线、窄窗口、左右布局交换和相关侧栏显隐后，坐标仍须一致。
- 桌面自动化用 `scripts/integrate.ps1 -Restart -Automation`（已部署时 `-RestartOnly -Automation`）在会话保护下首次启动即带参数，端口见 `src-tauri/src/lib.rs` 的 `WEBVIEW2_AUTOMATION_PORT`；验收结束跑 `-RestartOnly` 恢复普通启动并关闭调试端口。从该端口的 `/json/version` 取完整 browser WebSocket URL，每次调用传给 `agent-browser --session <任务名> --cdp`。先用 `tab <targetId>` 选中目标，再加布尔开关 `--pin-tab`；该开关不接收 ID，目标消失即停止。保留原实例时固定本轮新增 target，关闭共享 browser 会影响原窗口，只清理本轮实例。只对目标区域取 snapshot；`errors --json` 按首行去重，定位时再取堆栈。
- 应用重启后，使用新的 `--session <验收名>` 连接当前 CDP，并重新选择目标。复用会话可能保留旧目标错误；只将新会话中复现的错误归因于当前版本。
- 自动化操作 CLI 输入框时，派发 Enter 前先断言目标浮层（Skills、历史补全）存在；浮层未打开时 Enter 会把草稿发送给真实 CLI 并消耗用量。
- PowerShell 中的 Agent Browser 引用参数用引号传入，如 `click '@e1'`；截图按当前 CLI 帮助指定项目临时目录，并以返回路径核对实际落点。
- 宽、窄窗口验收使用 Tauri 原生窗口尺寸，在允许范围内调整并恢复原尺寸；不要对桌面 WebView 使用 `set viewport` 或设备模拟。若已有覆盖，解除持有覆盖的自动化连接并清除设备尺寸覆盖，不用关闭应用恢复。核对页面视口、原生窗口客户区与系统缩放匹配后再交付；仅新建 CDP 连接执行清除不代表原连接的覆盖已解除。
- 白边、整体偏移或裁切先比对真实窗口与页面视口，再查目标元素的 `getBoundingClientRect()` 和滚动范围；页面内部截图或根元素位于原点不能证明窗口显示正常。视口匹配后仍裁切才修布局，并验证原问题场景。
- 启动页定位 `WelcomeScreen.vue` 与 `src/styles.css` 的 `.welcome-screen`、`.welcome-panel`；最近项目较多或路径较长时，核对顶部入口可见、末条可滚动到达且无横向溢出。超高内容不能因居中落到负坐标。

## 手机 UI 实时预览

- 用户要求在电脑实时修改、预览手机 UI 时，先复用或启动 `npm run mobile:dev`，立即提供可访问的手机尺寸预览。入口与 Host 代理见 [vite.mobile.config.ts](../../../vite.mobile.config.ts) 和 [手机界面更新](../../../README.md#手机界面更新)；`mobile:build` 生成的静态页面不能替代热更新预览。
- 预览使用真实 `MobileApp`，分别核对页面可见、连接真实 Host、保存源码后热更新。HTTP 成功或构建通过不等于用户已看到界面；已有可用预览和确认直接复用。
- 浏览器控制不可用或打开操作被拒绝时，直接给链接让用户打开；只有工具观察或用户确认后，才表述为“已显示”。
- 用户继续使用的预览服务保持运行。预览迭代先确认 UI，正式交付再按发布流程打包，不为每次预览修改反复构建安装包。

## 验收

按本次 diff 核对上面的相关约束；只在修改相应文案、圆角、光晕或浮层定位时检查该项。构建与实际入口验收沿用发布技能的收口流程，正式构建包含前端检查。
